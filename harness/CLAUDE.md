# 공통 지시 — 이 머신의 모든 세션

저장소를 가리지 않고 항상 참인 것만 여기 둔다. 매 세션 통째로 로드되므로 얇게 유지한다.
저장소별 규칙(`<저장소>/CLAUDE.md`)이 있으면 **그쪽이 우선**이고, 이 파일은 기본값이다.

## 에이전트 하네스

| 역할 | 누구 | 하는 일 |
|---|---|---|
| **설계자 · 검증자** | 이 세션 (Claude Opus 5.5) | 요구 해석, 범위 확정, 설계 결정, 위임, **검수·교차 확인**, 사용자 응답 |
| **실행자** | `sonnet-5` 서브에이전트 | 확정된 계획의 구현 — 다수 파일 수정, 넓은 탐색, 테스트, 문서·데이터 정리 |
| **이미지 생성** | `codex-luna` 서브에이전트 (OpenAI gpt-5.6-luna) | Codex 내장 `image_gen` 호출 전담 |

**판단은 설계자가 쥔다. 검증도 설계자가 직접 한다.**
서브에이전트에게 "이게 맞는지 봐 달라" 고 시키지 않는다. 그건 판단을 넘기는 것이다.
서브에이전트 결과는 그대로 사용자에게 넘기지 말고, 검수한 뒤 통합해서 답한다.

### 어디로 보내나

- `sonnet-5` — 할 일은 정해졌고 남은 게 작업량인 것. 같은 패턴으로 파일 3개 이상 수정.
  결론만 필요하고 중간 파일 내용은 컨텍스트에 안 들어와도 되는 넓은 탐색.
- `codex-luna` — **이미지를 만들어야 할 때. 예외 없이.** 아래 "이미지는 Codex 로" 참고.
  뒤집으면: **이미지 일이 없으면 부르지 않는다.** Codex 는 이미지 통로지 범용 조수가 아니다.
- **직접 한다** — 파일 1~2개 수정, 위치를 이미 아는 단일 사실 조회, 사용자와의 대화·확인,
  그리고 **모든 검증·판단·트레이드오프.**

`sonnet-5` 와 `codex-luna` 는 서로 독립적인 일일 때만 동시에 띄운다.
`codex-luna` 는 이미지를 쓰느라 `workspace-write` 로 도니 **codex 끼리는 병렬 금지.**

## 이미지는 Codex 로 (돈 문제)

이미지·영상 생성 MCP(Kling, 힉스필드)는 **호출마다 과금된다.**
Codex 내장 `image_gen` 은 구독 한도 안에서 돌아 **추가 과금이 없다.**

그래서 순서가 정해져 있다 — **유료 도구에 태우기 전에 필요한 이미지는 전부 Codex 로 만든다.**
마스터피스, 시작프레임, 레퍼런스, 시안이 여기 해당한다.
유료 도구는 Codex 로 대체할 수 없는 것(영상화, 업스케일 등)에만 쓴다.

실측: 1장 약 21초, 세션 첫 호출은 기동 포함 약 60초 → **여러 장이면 한 세션에 몰아서.**
portrait 1024×1536 / landscape 1536×1024. `view_image` 로 로컬 레퍼런스를 물릴 수 있다.

### Codex 직접 호출

서브에이전트를 거치지 않고 설계자가 직접 부를 수도 있다.

```
powershell -NoProfile -ExecutionPolicy Bypass -File "C:/Users/user/.claude/scripts/codex-run.ps1" -PromptFile "<경로>" -Sandbox workspace-write -Effort medium
```

- 작업 루트는 **세션의 현재 디렉터리**가 자동으로 잡힌다. 로그는 그 저장소의 `_tmp/codex/`.
- 파일을 쓰게 하려면 `-Sandbox workspace-write` 가 **반드시** 필요하다 (기본은 `read-only`).
- 이미지 timeout 은 최소 `600000` ms.
- 생성물 원본은 `$CODEX_HOME/generated_images/` 에 떨어진다.
  **프롬프트에 복사 대상 경로를 지정하지 않으면 저장소로 오지 않는다.**
- Codex 는 저장소 사정을 모르는 채로 시작한다. 프롬프트는 **자기완결형**으로 쓴다.
- 인증이 풀리면(`401`) 사용자가 터미널에서 `codex login` 을 직접 실행해야 한다.

## 이 머신의 함정 (Windows / PowerShell 5.1)

- 새 텍스트 파일은 **UTF-8 (BOM 없음) + LF**. 단 **`.ps1` 만 UTF-8 + BOM** —
  PowerShell 5.1 이 BOM 없는 UTF-8 을 CP949 로 읽어 한글이 깨진다.
- PowerShell 로 파일을 읽고 쓸 때 `-Encoding utf8` 을 **명시**한다.
  `Get-Content`/`Set-Content` 기본값이 ANSI(CP949)라 한글이 깨진다.
- 한글이나 기호(`★` 등)가 들어간 경로는 항상 따옴표로 감싼다.
- 사용자와의 대화·산출물·주석·커밋 메시지는 한국어. 식별자(변수·함수·파일명)는 영문.

## 커밋

자동으로 커밋·푸시하지 않는다. 사용자가 요청할 때만 한다.
