**지금 실제로 돌리는 것은 S6(롱폼 → 채널 강의형 쇼츠)** — 10-13~14 빡이사DB 01~04편으로 흐름·도구·점검기가 굳었다(`references/s6-longform-shorts.md`). S1~S5 는 아직 뼈대다. 세 저장소(`한비즈-롱폼자동화` · `한비즈-쇼츠광고` · `D:\영상제작`)에서 사장님과 쌓은 규칙·통과/반려·워크플로우를 정독해 숏폼에 맞게 옮겼다. 어디서 무엇을 가져왔는지는 `references/sources.md`.

## 2. 한 편 흐름 — 단계 이름 (상세 `workflow.md`)

```
①받기 → ②조사·팩트체크 → ③구조·대본 ─[확인①]→ ④콘티 → ⑤소재·시안 ─[확인②]→
⑥만들기 → ⑦조립 → ⑧소리·마감 → ⑨살피기 → ⑩넘기기 → ⑪배우기 ─(반려: 그 컷만 ⑥으로)
```

- **모드 A 지시형(기본)**: 사장님이 지시·구간·연출을 말씀 → 위 흐름. 멈추는 곳은 확인①(대본·콘티)·확인②(시안·스토리보드, 유료 발주 전) 두 곳.
- **모드 B 자동형(설계만, 미구축)**: 원문·대본 한마디 + «느낌» → 템플릿 서랍에서 골라 퇴근 전 렌더 → 아침 검수. 밤에는 묻지 않고, 유료 영상화는 하지 않는다(«유료 후보»만). 근거는 롱폼 `auto-pipeline.md` 설계 v1(사장님 10-08 지시·10-12 확정) — 숏폼판은 `workflow.md` 5장.
- **편 유형 S1~S6**(`workflow.md` 2장): S1 사람 설명형(정면 1인 + 자료) · S2 상황극(대화형 촬영) · S3 소재 몽타주 + 나레이션 · S4 AI 영상 중심 · S5 말 없는 모션그래픽·타이포 · S6 롱폼 원문에서 쇼츠 뽑기(**운영 중** — `s6-longform-shorts.md`). 한 편 안에서 섞인다.

## 4. 사장님 상시 규칙 — 매 편·매 장면 (반려에서 나온 것, «…»는 원문 근거)

**받기·사실**
- **정독 + 요구 대장** — 받은 링크·파일은 한 줄·한 장면도 건너뛰지 않는다(영상은 `ref_study` 시트 전부 + 말 전부). 요구 하나에 번호 하나·원문 위치. 다 읽은 뒤 대장을 원문과 한 번 더 대조(10-08).
- **팩트체크 먼저** — «제조업 최신정보로 정독을 통한 팩트체크를 먼저하고 진행해야해»(10-12). 숫자는 공식 원문에서 설계자가 직접 대조한 것만, 못 찾으면 «못 찾음»(옛 값으로 대체 금지). 반올림은 아래로(4조 7,143억 → 4조 7천억).
- **숫자를 지어내지 않는다** — 화면 글·자막·카드의 숫자는 말·자료에 나온 것만. 업체명 ○○, 번호 010-0000-0000, 계정 ID·고객 정보가 보이는 실자료 금지(«업체명 나오면 문제 생길 수 있어서 그냥 연출로» 10-01).

**구조·대본**
- **말의 구조가 영상미보다 먼저** — «이상하게 문의를 넣고 싶지 않다 … 이대로 나가면 DB 엄청 안 뽑힐 것»(광고주 09-23), «DB감도가 좋지않았다 해서 기존 레퍼런스보고 검증된 구조로»(10-12). 검증된 구조를 뼈대로 하고, 학습한 모션그래픽·타이포는 자료 설명 구간에(`structure-playbook.md`).
- **쉬운 말 · 숫자 하나** — «너무 어렵대 언어들 숫자들 시청자가 계산하게 시키는거자체가 안읽히는 광고일거같다고함»(10-12). 한 문장에 숫자 하나, 비교·곱셈·%를 시청자에게 계산시키지 않는다.
- **레퍼런스는 짚은 요소만** — 형식 통째로 베끼지 않는다(«걸작의 영상미만 참고» 09-28). 후킹은 구조·느낌만, 첫 대사는 새로 쓴다(«첫대사후킹까지똑같은데 … 같은느낌의 후킹인데 대사가 좀 다르게» 10-12).
- **첫 5초 안에 후킹 요소 3개 이상**, 오프닝은 영상(이미지로 시작 금지)(09-27·09-28).

**연출**
- **앞뒤 맥락 먼저** — «모든 작업은 무조건 앞뒤 맥락 파악해서 연출하라»(10-07). 기록에 «앞/뒤 맥락» 줄.
- **구도는 그 말이 실제로 일어나는 자리** — 통과 틀 복붙 금지, 비교 연출 연달아 금지(10-07 «왜 핸드폰으로 연출했어 … 실제 세팅 페이지에서 설정하는 느낌으로»).
- **도형 짜깁기 금지** — 사물은 Codex 이미지·실제 이미지·녹화 실화면(«도형으로 수준 낮은 짜깁기 원하지 않음» 10-07). UI 그 자체(버튼·입력칸·진행선)는 코드로 그려도 된다.
- **단색 배경판 금지 · 고급감** — «주황색 단색배경 클로드가 자주만들어주는 느낌이라 중복컨텐츠 느낌»(10-12). 큰 바탕은 사진·질감·UI 카드를 겹친 복합 장면.
- **화면 글은 말 따라 쓰지 않는다** — 말을 받치는 개념어(«심리학적 요소처럼, 말 따라 하지 말고» 10-08), «» 따옴표 대사 금지(««» 이렇게 대본 넣는 거 별로 안 이뻐»), 말을 문장으로 옆에 다시 띄우지 않는다(«시선이 분산되는데?» 10-12).
- **글자·숫자·로고는 렌더러가 그린다** — 영상·이미지 생성 모델에 한글을 맡기지 않는다(«비타민B» → «에터민B»).
- **인지할 텀 0.6초** — 새 요소는 혼자 0.6초 이상, 한 문장에 새 요소 2~3개(«연출이 전체적으로 급해서 정신없는 느낌» 10-07). 글자가 다 보이기 전에 넘어가지 않는다(«중간에 글이 나오지도 않고 화면이 넘어가는데?» 10-12) — 글자 등장은 머무는 시간의 1/3 안에.
- **영상미 기본값** — 등장 4~8프레임 감속 · 오버슈트(튕김) 0 · 3색(비교는 쪽마다 색 하나) · 핵심어 하나만 강조 · 흔들림 연출 금지(«흔들리는 연출 별로» 10-12) · 글리치 한 편 한 번 · HUD 라벨·페이지 번호 금지(«위에 한비즈랑 페이지숫자세는거 없애줘» 10-12).
- **판·카드는 구멍 없이** — 알파 255, 모서리 반경 12~14(«구멍 뚫린 부분에 영상이 비치는 게 안 좋으니 색을 채워라» 09-22).
- **까만 화면·상관없는 이미지·이모티콘 소품·중복 자막 금지**(09-28).
- **(S6) 자료는 «요소 하나를 크게», 말 따라 쌓고 하드컷** — 실화면 녹화는 **본편 실제 화면을 실명이 안 들어오게 잘라** 크게 쓴다(다시 그린 UI 는 «AI로 다시 만든 티» — 10-15), 가림은 꼭 필요한 한두 곳만 깔끔한 ○○ 로, 끝 녹임·줌팬으로 정지 화면 움직이기 금지, 추상 말은 얼굴(«3편은 모자이크 떡칠» «위아래 안개낀것같은느낌 + 키프레임만으로 영상대체» 10-14). 상세 `s6-longform-shorts.md` 6장.
- **(S6) 자료는 자막 위에서만 · 끝은 글자를 가르지 않게** — 확대도 자막 위 영역 안, 기준점은 글자 시작 쪽(«레이아웃겹» «위아래가 너무잘려있고» 10-14). 상세 `visual-rules.md` 6장.

- **(S6) 자막 시각은 대본 글자 강제 정렬, 나누기는 의미 단위**(«인스턴트 양식 / 같은 경우에는» 10-14) — 받아쓰기 시각 금지. 상세 `captions.md`.

**소리**
- **효과음은 그래픽·동작에 붙는다**(컷이 아니다, 사장님 편집 실측 97%). 구운 효과음도 그 변화가 자막 위에서 보여야(«화면은정지인데 효과음은 띠링?» 10-14). 뜻(긍정·부정·중립)·그림(도장엔 도장 소리)에 맞춘다(«천만 원 미만인데 왜 축하 효과음» 10-08).
- **같은 소리 짧은 주기 반복 금지**(«내가 제일 경계하는건 연달아쓰는거지» 10-02) · 자연 길이 · 효과음끼리 겹치지 않게(«겹치는부분때문에 듣기싫어» 10-12) · 마림바·실로폰·합성 벨 금지(«실리폰소리 되게 듣기싫»).
- **BGM 깔린 편은 효과음이 음악에서 «튀어나와야»** — «효과음이 너무 작고 효과음볼륨도 제각각 … 톡톡 툭툭 효과음이 튀어나와야하는데»(10-12).
- **청음본·A/B 듣기를 요청하지 않는다**(10-02), **소리는 귀로 못 들었으면 «못 들었다»고 보고**한다.

**운영**
- **물어보지 말고 만들어서 보여 준다** · **정한 건 즉시 파일로** · **작업이 끝나면 납품 폴더를 탐색기로 연다**(10-08 «아니 작업 끝나면 항상 폴더 열어 줘»).
- **납품 파일**: 고친 판은 같은 이름 제자리 덮어쓰기(이미 프리미어에 들어가 있다 — 폴더 지우기·이름 바꾸기 금지), **내용 개편·«새 판» 요청은 새 폴더 `_vN`**(«개편사항은 덮어씌우지말고 v2로» 10-12). 잠긴 파일은 남기고 알린다.
- **유료 생성은 장면당 한 건**(«두개를 뽑아서 하나를 쓰면 확정적으로 크레딧 하나분량의 영상을버리는거잖아» 09-23). 이미지는 Codex 가 먼저.
- **규칙 누락 방지** — 시작 전·장면마다·납품 직전에 문서를 다시 연다(«규칙 누락 현상 심함» 09-28). 새 피드백은 **규칙 한 줄 + 점검표 한 줄**.
- **검증하지 않은 것을 «됐다»고 쓰지 않는다** — «지웠다»고 보고한 요소는 렌더 결과를 원본 해상도로 잘라 확인(10-12 HUD 남은 채 «없앴다» 보고 → «이런것좀 없애줘,,»).

## 6. 세로 수치 — 한 곳 (`references/vertical-spec.md`)

확정값은 그 문서에만 적는다. 확정된 것: **설명형 자막 = A2 불투명 회색 띠**(10-08) · **S6 배치**(위 띠 440·내용 칸 440~1710·자막 y 1440·자료 영역 내용 칸 0~925, 10-13~14). 나머지 유형의 사람 자리·자막 y·fps·안전 영역·효과음 크기는 **☐ 재서 채울 칸**이다. 가로(1920×1080) 값을 그대로 쓰지 않는다.

## 9. 보고 형식
