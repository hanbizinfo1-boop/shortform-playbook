# 한 편 흐름 — 지시부터 완성본·피드백까지 (학습 전 뼈대, 2026-10-13)

SKILL.md 2장의 단계를 풀어 쓴 것이다. 단계마다 **무엇을 읽고 · 무엇을 남기고 · 어디서 멈추나**만 적는다.
뼈대의 근거: 쇼츠광고 `workflow.md`(P0~P7·T1~T4·확인 두 곳, 10-08) + 롱폼 `auto-pipeline.md`(①받기~⑨배우기·템플릿 서랍·밤샘 무인, 10-08 지시·10-12 확정) + 영상제작 분양4 장면 뼈대 9단계(learn_A) + 병행작업 운영(요구 대장·팩트체크·스킬 반영 대기, 10-12).
**☐ 표시는 첫 건에서 정해지면 이 문서와 `기록/작업기록.md` 에 바로 적는다.**

## 0. 한눈에

```
지시 ─▶ ①받기 ─▶ ②조사·팩트체크 ─▶ ③구조·대본 ─[확인①]─▶ ④콘티 ─▶ ⑤소재·시안 ─[확인②]─▶
⑥만들기(컷마다 루프) ─▶ ⑦조립 ─▶ ⑧소리·마감 ─▶ ⑨살피기 ─▶ ⑩넘기기 ─▶ ⑪배우기 ─┐
                          ▲                                                        │
                          └──────────── 반려: 그 컷만 ⑥으로, 같은 이름 덮어쓰기 ───┘
```

- 판단은 ③④ 두 곳에 모은다. ⑥~⑩은 콘티·배치표를 그대로 실행하는 기계 단계다 — 그래야 나중에 모드 B(무인)가 된다.
- 보여 드리는 단위는 **한 편**(완성본 또는 확인용 초벌). 반려는 컷 번호로 받아 그 컷만 다시.

## 1. 단계별

### ① 받기 — 정독 + 요구 대장
- 받은 링크·파일·녹음·레퍼런스를 **처음부터 끝까지** 읽는다(10-08 «하나라도 빠짐없이»). 영상은 `tools/ref_study.py` 시트 전부 + 말 전부, 문서는 전 쪽(표·각주 포함). PDF 글자는 pymupdf(pdftotext 는 한글이 깨진다). 스크립트로 그리는 웹페이지는 curl·WebFetch 로 본문이 안 읽힌다 — 브라우저로 열거나 «못 읽음».
- **요구 대장**(`기록/작업기록.md`): 번호 하나에 요구 하나 · 원문 위치 · 인용 · 산출물. 분류는 병행작업 방식: A 사장님 지시 / B 회의·녹음 / C 사장님 확정 답 / D 쓸 수 있는 사실(출처) / E 쓰면 안 되는 말 / F 새로 찾은 것 / G 열려 있는 것.
- **읽은 범위 표**(파일 · 쪽/시각 · 읽음)를 남긴다. 다 읽은 뒤 대장을 원문과 한 번 더 대조.
- 건 정보: 건 이름·목적·대상·길이·플랫폼(유튜브 쇼츠/릴스/틱톡/메타 광고)·원본 위치(경로만)·**사용 허락 범위**(초상권·음원·출연 동의)·편 유형(2장)·범위 규칙(분양 캠페인 규칙? 사장님 효과음만? 편끼리 재사용 금지? 음성 배속?)·납품 형태(⑩).

### ② 조사·팩트체크
- 대본에 들어갈 숫자·조건은 **공식 원문**(공고 hwpx·기관 누리집·고객 자료)에서 **설계자가 직접 문구를 대조**한 것만 «확정». 실행 에이전트 조사는 단서일 뿐이다(병행작업 10-12: 13개 문구 직접 대조 → «일치»만 사용, 공지 페이지를 직접 못 연 금리 3.42% 는 «미확인 — 대본에 안 씀»).
- **근거 표**를 대본과 한 쌍으로: 문구 · 숫자 · 원문 위치 · 원문 인용 · 일치/미확인. 날짜 병기(«2026년 10월 기준»), 제작 직전 재확인.
- 원문 조건을 뒤집는 표현은 금지 목록으로 뽑는다(«언제든 신청 가능» ↔ 예산 소진 시까지, «받을 수 있다» ↔ 심사·감액 가능, 고정 금리처럼 보이는 숫자, «이내» 빠진 한도 등 — `structure-playbook.md` 4장).
- 못 찾은 것은 «못 찾음». **옛 값으로 대체하지 않는다.**

### ③ 구조·대본 → **확인①**
- `structure-playbook.md`: 편 유형에 맞는 **검증된 구조**(레퍼1 7구간 · 분양 상위 광고 7공통 · 쉬운 말 골격 등)에서 시작한다. 사장님·고객 원문이 정본, 이쪽이 쓰면 «초안».
- 첫 5초 후킹 요소 3개 이상 · 한 문장 숫자 하나 · CTA 고정 + 버튼 · 근거 없는 문구·숫자 없음.
- 길이 어림: 음절 ÷ 5.5음절/초(쇼츠광고 실측 기준). 1분 이내(한비즈 광고 기본, 10-08 «1분이내라는뜻»).
- 납품: 안마다 PDF(대본 + 장면 설계) · «대본만» PDF · **드래그 복붙용 TXT(시간 없이)**(병행작업 10-12 «시간도 넣지말고 그냥 드래그 복붙가능하게끔»).
- 확인①에서 보여 드리는 것: 대본 + 줄 × 화면 표(줄 · 시각 어림 · 그림 · 한 줄 연출) + 근거 표.

### ④ 콘티
- 줄마다 **상황(PB)** 을 붙이고(`situation-playbook.md`), 그 강령이 허락한 서랍·템플릿에서 그림 하나를 고른다(`drawers.md`). «그 말이 실제로 일어나는 자리»를 `why` 한 줄로 못 쓰면 다음 후보.
- 같은 기법·비교 연출·같은 전환이 연달아 붙지 않는지 표에서 먼저 본다. 컷이 «감정 변화 / 액션 진전 / 압박 증대» 중 하나도 못 하면 지운다.
- 장면 스펙(촬영 지시서형) — EXACT STRINGS(화면 글 목록, 문장부호까지) · 단어 시각표 · 금지 목록(`visual-rules.md` 3장).

### ⑤ 소재·시안 → **확인②**
1. 목소리: 녹음본 또는 TTS(☐ 상업용 TTS 키 없음 — 원본 기록은 구글 Chirp3·edge-tts 시험·Azure 집행 계획). TTS 를 쓰면 한국어 원어민 음성인지 먼저 확인(09-27 «외국인 말투» 반려).
2. 대본 원문에 정렬 → 줄·단어 시각(받아쓰기 글자는 쓰지 않는다). 자막은 말 시작으로 당기고 0.05초 앞세움.
3. **Codex 이미지 한 세션에 몰아서** — 시안·시작프레임·배경·소품. 바탕 시안은 서로 다른 방향 2~3장.
4. 실자료·견본은 출처를 `소재/이미지-출처.md` 에.
5. 확인②: 스토리보드(컷별 «다 나온 모습» 정지) + AI 영상 컷 시작프레임 후보. **사장님이 고른 것만** 유료 1건.

### ⑥ 만들기 — 컷마다 루프
`앞뒤 맥락 → 단어 시각 → 구도 → 그림 → 조각·정지 스토리보드 → 겹침 검사 → 렌더 → 효과음 → 프레임 확인 → 기록`
- 렌더 길: 글자·UI·숫자·로고 = html_motion(코드) 또는 AE / 사진·사람 = Codex 이미지 / 실사 움직임 = Codex 시작프레임 → 유료 1건(`ai-video.md`). 상세 `visual-rules.md` 1장.
- 정지 스토리보드가 오류를 가장 많이 잡았다(빡이사 13·17·19·21·22 — 주소창·손가락이 글 가림·글자 깨짐·겹침).
- 장면 끝은 컷 경계보다 1프레임 이상 앞, 빈 무대 1초 이상 금지(롱폼 10·09 사건).

### ⑦ 조립
- **배치표(컷 × 줄 × 시각 × 전환 × 자막 × 효과음 계기) 한 장이 편집의 정본.** 사장님 프리미어 초안이 오면 초안의 컷 길이·순서가 정본(바꾸면 보고에 적는다).
- 편집 문법 출발값(분양 쇼츠 세로 실측 — 한비즈에서 같은지 ☐): 컷 평균 1.6~2.3초(긴 홀드·기본 박·연타 섞기) · 전환 20컷 중 6~10곳(0.25~0.35초, 종류를 돌려 쓰고 연속 금지) · 섹션 끊을 때만 흰 플래시 2프레임 · 자료는 2초 이상·다음 줄까지 끌고 감 · 배경은 정지, 글자·그래픽만 움직임. 상세 `vertical-spec.md` 4장.
- 도구: ☐ 쇼츠광고 `edit_plan.py`/`edit_render.py`/`edit_xml.py` 이식 후보(합성 소재 시험 통과, 프리미어에서 XML 열기는 미확인).

### ⑧ 소리·마감
- `sfx.md` — 형식(말 있는 편 / BGM 깔린 말 없는 편 / 분양 캠페인)부터 정하고 그 규칙만. 마감 −14 LUFS · 트루피크 −1.5dB 이하가 출발값(마감 음량은 건마다 배치표에 — 원본에 −11·−14 가 섞여 있다).

### ⑨ 살피기
- `checklist.md` 해당 표를 한 줄씩 → 결과를 보고에. 모아보기(`fps=2,scale=240:-1,tile=8x1`)로 전 구간 눈 확인. 글자는 원본 해상도로 잘라 본다. 소리는 «못 들었다».

### ⑩ 넘기기
- 기본(쇼츠광고 10-08 «내가 프리미어에 넣어서 적용할게»): `납품/<건>/` 에 **프리미어 XML + `media/` 층별 소재**(배경 컷·그래픽 알파 MOV·자막 알파 MOV·효과음 낱개) + 확인용 미리보기 mp4 + SRT(사장님이 자막을 직접 만지실 수 있게). XML 은 XML 만으로 다시 조립해 미리보기와 대조한 뒤 드린다. 사장님이 «XML 말고 영상 통으로»라고 하신 적도 있다(09-29) — ☐ 건마다.
- 고친 판은 같은 이름 제자리 덮어쓰기, 내용 개편·새 판은 새 폴더 `_vN`. 보고 직전 `납품/` 을 탐색기로 연다.

### ⑪ 배우기
- 사장님 말씀은 원문 그대로 `기록/작업기록.md` + `feedback-log.md`. 효과음 반응은 실사용 기록(☐ 이식 시 `tools/data/예능효과음-실사용.json`).
- **사장님은 저장본으로 먼저 답하신다** — 아침·다음 세션 첫 일은 사장님 프리미어 저장본(자동저장본 사본) diff 읽기: 볼륨(0dB = 0.17783), 바뀐 컷, 지운 장면, 고른 시안(롱폼 bisa-learning: 로고 효과음 «좋아»의 정체는 저장본의 시안 C).
- 통과 표현 사전: «통과 다음» «오케이 다음» «좋아» «고고» = 통과 / **«일단 이건 통과 근데 …» = 통과 + 새 규칙** / «수정x 다음편부터» = 소급 금지 / «잘못보냈다» = 직전 메시지 무시.
- **성과 데이터**(☐ 받는 길 미정): CTR·DB 단가·DB 수. 3안 타이포는 «주말간 돌려보았는데 DB감도가 좋지않았다»(10-12)로 방향이 바뀌었다 — 영상미 평가와 별개로 성과가 구조를 결정한다.
- 굳은 규칙 → SKILL 4장 **규칙 한 줄** + `checklist.md` **점검표 한 줄**(+ 기계로 볼 수 있으면 점검기).
