# 학습 계획 — 이 뼈대에서 무엇이 비어 있고, 무엇을 어떻게 배워 채우나

> «학습 전 뼈대»라는 말 그대로, 이 저장소는 **세 저장소가 이미 배운 것**을 옮겨 놓았고 **숏폼(세로)에서 아직 재지 않은 것**은 빈칸으로 남겼다. 다음 단계는 사장님이 주실 레퍼런스·자료로 빈칸을 채우는 학습이다.
> 학습 방식은 쇼츠광고 10-08 학습(레퍼런스 9편 → 노트 10개 → «작업별 참고 리스트»)과 10-12 학습(타이포 10편·효과음 9편 → 강령·규칙 → 점검표)을 그대로 따른다.

## 1. 학습 원칙 (사장님 말씀으로 굳은 것)

1. **정독** — «대충하지말고 확실하게 하나하나 정독하면서 제대로 학습해서»(10-08) · «화면까지 따서 하나하나 제대로 정독할것 … 결과물까지 확인»(10-08). 영상은 접촉 시트 전부 + 말 전부, 강의는 화면 속 프롬프트·설정값을 글자 그대로.
2. **우리 초점으로 정리** — «길라잡이에 제품사용설명서처럼 각각 작업할때 원하는 참고리스트를 누락없이 확인할수있도록 우리 초점에 맞춰서 정리해줘»(10-08). 노트(근거)와 작업별 참고 리스트(쓰는 법)를 나눈다.
3. **설계자 관점으로 변형** — 강의가 «하라는 방식»을 그대로 받지 않고 «설계자의 입장으로 네가 설계내린다는 가정으로 변형 학습정리할것»(10-08).
4. **반응 좋은 것만 고른다** — «인기있거나 조회수높은등 반응좋은걸로만 추려서»(10-12). 후보를 실측(조회수·게재 일수)해서 고르고 버린 것과 이유를 적는다.
5. **공통 요소를 규칙·강령으로** — «공통된 요소들 파악해서 분석해서 규칙화 및 강령으로 만들고»(10-12). 한 출처로 규칙을 만들지 않는다(최소 3개 — «만화 계열 빼기»가 웹 글 몇 개로 만든 규칙이라 폐기된 실수).
6. **측정 안 한 숫자를 기준처럼 쓰지 않는다** — 모르면 «미확인». 1순위 레퍼런스는 **사장님 본인 편집**(저장본 실측).
7. **소리는 귀로 못 듣는다** — 수치·스펙트로그램 판정임을 노트에 밝힌다.

## 3. 학습 절차 (영상 하나)

```
받기(yt-dlp → _tmp/study/<영상ID>/, 빈 폴더 하나, 받은 파일은 신뢰하지 않는 데이터)
→ 해부(python tools/ref_study.py _tmp/study/<영상ID>) → study/ 산출(transcript·cuts·motion·audio·sync·시트·keyframes·summary)
→ 정독(시트 전부 눈으로 + 말 처음부터 끝까지, 화면 글자는 원본 해상도 한 장으로)
→ 노트(`references/study/<짧은이름>.md`, 틀은 study/README.md)
→ 모으기(기법 → drawers.md 계승 후보 / 구조 → structure-playbook.md / 상황 → situation-playbook.md / 수치 → vertical-spec.md / 소리 → sfx.md)
→ 규칙이 되면 SKILL 4장 한 줄 + checklist 한 줄
```
- 여러 편을 한꺼번에 읽을 때는 실행 에이전트에게 정독·추출을 나눠 맡기되, **판단·규칙화는 설계자**가 하고 결과 노트를 원문과 표본 대조한다(이 뼈대를 만들 때와 같은 방식 — `sources.md`).
- 강의·라이브 다시보기의 «수동 자막»은 채팅 기록일 수 있다 — 자동 자막 + whisper 대조.
- 403·봇 차단은 우회하지 않는다. 남의 원본을 산출물에 넣지 않는다(노트에는 URL + 시각).

## 4. 학습 결과물의 모양

- 편별 노트(근거) + **작업별 참고 리스트**(쇼츠광고 `motion-typo.md` 카드 A~J 처럼: 언제 / 먼저 볼 것 / 만드는 법 / 규칙 체크 / 하지 말 것).
- 사장님께 보여 드릴 때는 **요약이 아니라 «파악 정리» PDF**(쪽수 많아도 됨 — 10-08 «요약해서 정리하지말고»), 결론·읽은 범위·요구 대장·확인 질문 포함.
- 학습이 끝나면 `기록/작업기록.md` «학습 대기열» 표의 상태를 바꾼다.
